# Adaptive protocol dogfood

This is the bounded, temporary-target-only Block 11 live-behavior evidence
surface. It composes
the maintained inline-correction, bounded-candidate, program-revision,
target-class, and adaptive-decision checkpoints; it is not another decision
engine and conveys no application, release, policy, mission, lifecycle, or
external-effect authority.

Run the frozen matrix from a clean exact revision:

```bash
/usr/bin/python3 implement-tracker-blocks/scripts/adaptive_protocol_dogfood.py --pretty
```

The result separates opaque candidate review inputs from observed dispositions.
Each blind input contains the raw comparison, eligibility, or Stop evidence and
its own root, with no source case name or expected result. It also retains
executed temporary-target bytes and stdout for the inline and full-autonomous
ordinary cases, the applied reviewed tracker bytes plus automatic resume for
the structural case, owner handoff posture, total human requests, bounded
candidate usage and retirement, accepted-Block remediation, all four authority
modes, and the exact maintained recovery checks. Volatile temporary paths and
Git commit identities are validated inside each run but excluded from the
result projection; the retained bytes, diffs, observations, semantic handoffs,
and source revision regenerate the same exact result root from a Git checkout
or exact Git-less archive.

The demonstrated envelope is deliberately small:

- an ordinary temporary target corrects a wrong owner and unsupported
  generalized layer inside the current Block, executes the corrected bytes,
  and leaves the governing tracker unchanged;
- a justified incumbent returns through the cheap unchanged path;
- implementation comparison opens only when read-only evidence is
  insufficient and closes with one incumbent authority plus a non-authorizing
  handoff or retirement;
- exact structural evidence is independently reviewed, applied through the
  existing program owner in a temporary target, and rehydrates the automatic
  resume action after a simulated lost return from the accepted review and
  range amendment;
- a defect in accepted work preserves the accepted history root, adds and
  closes one remediation Block against the observed effect, preserves the
  unaffected safe frontier, and resumes the displaced work;
- Software Factory self-work uses the same semantic paths while keeping
  application and adoption with the existing normal owners;
- full-autonomous ordinary work reaches an observed normal-owner effect with
  zero human requests, while an unavailable external act is narrowly deferred
  and safe work remains;
- fixed remains record-only, recommend remains recommendation-only after its
  independent review, and reviewed-autonomous retains the consequential
  application boundary;
- stale, duplicate, interruption, losing, inconclusive, reopened-outcome, and
  rejected-structure checks reuse the maintained owner regressions.

The matrix creates, writes, commits inside, and deletes only its disposable
repositories plus in-memory/captured canonical evidence. It applies the
dogfood correction and structural revision inside those temporary targets so
the observed effects are not inferred from stage records. It does
not edit the governing repository tracker, cut over a live candidate, mutate
live configuration, install or release a skill, contact an external service, or
claim statistical superiority. A green matrix is necessary bounded evidence,
not a general capability claim; completion still requires exact-revision
independent review of the blind inputs, applied bytes, observed output, and
resume roots.
