# Integrated Factory-evolution dogfood

This reference defines the terminal, temporary-owner-only evidence runner for
the coupled adaptive implementation and Factory-evolution loops. It supplements
the smaller within-run adaptive-protocol matrix; it does not replace any normal
authoring, implementation, supervision, evaluation, release, or outcome owner.

## Run the frozen matrix

From an exact clean Software Factory source revision, with the current three
stable skill links available at `/Users/ethanstillman/.codex/skills`, run:

```bash
uv run --python 3.14 python \
  supervise-tracker-runs/scripts/factory_evolution_dogfood.py \
  --pretty \
  --output /tmp/software-factory-integrated-dogfood-result.json \
  --evidence-output /tmp/software-factory-integrated-dogfood-evidence.json
```

The command obtains an exclusive lock and recreates only
`/tmp/software-factory-integrated-dogfood-v1`. It deletes that disposable
workspace when the run finishes. Pass `--workspace` only for another explicit,
bounded disposable path. The command never accepts a live supervision, release,
or install root.

## Evidence envelope

The matrix uses production `supervision_log.py` parser commands and Factory
evolution functions against one disposable Git target. It retains:

- one admitted signal, reviewer handoff, normal `implement-tracker-blocks`
  candidate, executed candidate proof, executed incumbent comparison, sealed
  evaluator disposition, temporary normal-release-owner adoption, installed
  behavior observation, independently shaped completion record, terminal
  effective outcome, and duplicate outcome reuse;
- the identical consumed checkpoint with zero event and cycle-directory delta,
  zero candidate or authoring handoff, and zero model, reviewer, or human call;
- one separately admitted candidate that is independently rejected, reaches
  terminal retirement, preserves incumbent authority, and creates no second
  release activation;
- the lower-power tracker-only shortcut and unsupported generalized detector as
  reviewed but rejected paths, with no structural authoring because the Block
  and program contract did not change;
- all four adaptive authority modes from the maintained within-run matrix,
  including zero ordinary human requests in full autonomy and narrow reserved
  external deferral; and
- current resolution and validation of the three stable skill symlinks plus a
  full-profile tracker verification invoked through the installed author skill.

The deterministic clock, temporary evaluator seed, temporary owner-root
material, target commit chronology, and closed semantic schema make the default
projection reproducible at one source revision and one current installed
three-skill release. It changes when either source or installed skill identity
changes and is explicitly nonauthorizing. Projection construction first
revalidates the exact raw result, each retained nested root, and every retained
semantic acceptance leaf. This establishes self-contained disposable proof,
not external authenticity or permission.

The separate `--evidence-output` JSON is the one frozen high-precision run. Its
Git target-owner currentness deliberately binds ref and reflog path/stat
identity, including device, inode, modification time, and change time. Those
exact provenance/currentness roots and their dependent event roots are
run-specific and must never be normalized. The semantic projection excludes
only the closed, enumerated run-instance fields; it never removes fields by a
root-name wildcard and cannot replace independent inspection of the raw run.

## Ownership and effect boundary

The temporary release owner installs real candidate archive bytes below the
disposable workspace and switches only its own `current` link. That installed
copy is executed and hashed before an effective outcome can be recorded. It is
not the live Software Factory release owner and cannot write
`~/.codex/software-factory-releases` or the stable skill links.

The evaluator key is deterministic, test-only material below the disposable
workspace. It proves the production signed-evaluator interface and exact role
binding; it is not a release, production, or external authority key. The final
source revision still requires a distinct independent exact-revision reviewer.

The runner must report every live-effect flag false. It performs no Gmail,
deployment, external-provider, live policy, live mission, lifecycle, global
skill-store, or live release mutation. A `promote` disposition in the retained
matrix is not permission to apply any live release.

## Interpret the output

High-precision evidence is the `--evidence-output` canonical JSON: packet, review, candidate,
comparison, evaluation, adoption, installed-effect, outcome, live-skill, and
operator-projection roots remain separate. The `human_report_projection`
contains only a concise derived summary and never becomes an adjudicating
source.

The default/stdout JSON is the deterministic semantic projection. It retains
the exact source revision and installed three-skill identity; winner owner,
disposition, one activation, installed proof, and adopted-effective posture;
consumed no-op zero deltas and calls; rejected loser, incumbent authority, and
zero activation; rejected lower-power/generalized paths and no structural
authoring; all four modes and human counts; operator/report postures and
counts; clean target state; and every false live/reserved effect flag.

Terminal acceptance requires independent inspection of the raw source inputs,
exact events and artifacts, temporary installed bytes and executed output,
selected and rejected paths, activation count, consumed-input no-op, losing
candidate history, live-skill resolution, authority-mode results, and all false
live-effect flags. Passing tests, populated artifacts, a `promote` value, or
documentation prose cannot substitute for those current observations.
